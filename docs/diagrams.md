# 본문 도해 규약

`public/images/**/*.svg` 아홉 장이 같은 문법을 쓴다. 새로 그릴 때도 이 문법 안에서 그린다.

## 무엇을 고쳤고 왜인가

처음 그린 도해는 칸이 크고, 칸마다 제목과 설명 두 줄이 들어 있고, 칸들이 격자에 늘어서
있고, 위에 "현장 / 엣지 / 서버 / 사용자" 같은 열 이름이 붙어 있었다. 정보는 다 있었지만
엔터프라이즈 아키텍처 도면처럼 읽혔다. 글을 읽다 만나는 그림이 아니라, 글과 따로 노는
표에 가까웠다.

Anthropic의 글에 붙는 도해와 비교해 네 가지를 바꿨다.

1. **칸은 이름만 갖는다.** 설명 두 줄을 칸에서 빼 칸 아래 작은 글로 내리거나, 선 위
   이름표로 옮겼다. 칸이 작아지면 그림이 한눈에 들어온다.
2. **색이 역할을 말한다.** 전에는 "중요한 칸만 초록 테두리"였다. 강조는 한 칸에만 쓸 수
   있어서, 나머지 칸들이 전부 같은 회색 덩어리가 됐다. 지금은 네 색이 각각 뜻을 갖는다.
3. **직각 대신 곡선으로 잇는다.** `H … V …`로 꺾으면 회로도가 되고, 완만한 베지어로
   모이면 "흘러든다"로 읽힌다.
4. **여백을 남긴다.** 그림은 판의 가운데에 작게 놓는다. 꽉 채우면 읽는 사람이 어디부터
   봐야 할지 알 수 없다.

## 색

| 이름 | 뜻 | 라이트 면 · 선 · 글자 |
| --- | --- | --- |
| `g` 초록 | 일이 실제로 벌어지는 곳. 공정 그림에서는 코드가 바뀌는 단계, 문서 그림에서는 정의가 사는 문서 | `#e7f0ea` `#4e8f74` `#1d6b4f` |
| `v` 보라 | 기준이 정해지거나 확인되는 곳 — 규칙 · 계약 · 판정 · 리뷰 · 게이트 | `#ecebf4` `#7d74ab` `#544a87` |
| `t` 주황 | 경계와 되돌아간 비용 | `#f7ebe3` `#c07a4e` `#9c4a15` |
| `q` 회색 | 맥락. 이 그림의 주인공이 아닌 것 | `#f4f1ea` `#cec8bb` `#57534a` |

주황은 지금까지 **나가는 쪽**에만 썼다. 앱 · 관리자 웹 · Merge 같은 출구와, 재작업
막대가 그것이다. 들어오는 쪽(센서 · Task · 변경)은 회색으로 두었는데, 대개 그림의
주인공이 아니라 이야기가 시작되는 자리이기 때문이다. 이 구분을 바꾸려면 아홉 장을
한꺼번에 바꾼다.

색의 뜻은 **그림 한 장 안에서** 고정된다. 같은 이름의 칸이 한 그림 안에서 색을 바꾸면
역할이 실제로 바뀐 것이어야 한다. `02-rule-dedup`에서 `AGENTS.md`가 정리 전에 회색이고
정리 후에 초록인 것은 그 사이에 정의를 품게 됐기 때문이다. 이유 없이 색만 다르면
읽는 사람은 규칙이 없다고 판단한다.

한 칸은 면 · 선 · 글자를 같은 색 한 벌로 쓴다. 색 변수는 각 SVG의 `<style>` 안
`.dg { … }`에, 다크 값은 `:root[data-theme='dark'] .dg { … }`에 들어 있다 — OS 설정이
아니라 사이트의 테마 토글을 따른다. 글자 대비는 라이트 기준 4.8:1 이상, 다크 기준
5.8:1 이상이다.

## 규격

- 넓은 화면용은 viewBox 폭 **960**, 좁은 화면용은 **360**. 글자 크기는 960 좌표계 기준
  칸 이름 15px(빽빽하면 13.5px), 선 이름표 13.5px, 칸 아래 설명 13px.
- viewBox의 세로는 그림 내용에 위아래 **32**씩만 더한 값이다. 판이 내용보다 크면 아래가
  비어 보인다. 내용의 경계는 `inkscape --query-all 파일.svg`의 첫 줄(x, y, w, h)로 잰다.
- **배경을 그리지 않는다.** 판(바탕 · 테두리 · 모서리)은 `global.css`의 `.prose svg.dg`가
  준다. SVG 안에 `rect.bg`를 두면 안쪽 `rx`와 바깥 `border-radius`가 배율에 따라 어긋난다.
- 칸은 `.n`, 이름은 `.l`, 선은 `.e`, 칸 아래 설명은 `.sub`, 판 제목은 `.hd`,
  묶음 점선은 `.grp`이다. 값을 재는 그림은 막대 `.bar`, 눈금 글자 `.tick`, 눈금선
  `.grid`를 쓰고, 판 안을 가르는 실선은 `.rule`이다. 막대는 칸과 달리 테두리 없이
  진한 면(`--*-text`) 하나로 칠한다 — 길이 자체가 값이라 옅은 면으로는 읽히지 않는다.
- **쓰는 클래스는 반드시 그 파일의 `<style>`에 있어야 하고, 선분에는 `fill:none`을 준다.**
  이름 클래스 `.l`은 색 클래스를 빠뜨려도 `--ink`로 떨어지게 기본값을 갖고 있지만,
  나머지는 그렇지 않다.
  SVG의 기본 `fill`은 검정이다. 규칙을 빠뜨리면 막대는 라이트에서 검은 덩어리가 되고
  다크에서는 배경에 묻히며, 선분은 넓이가 없어 아예 그려지지 않는다. 눈으로는 "그림이
  좀 심심하네" 정도로만 보여서 오래 남는다. 아홉 장의 `<style>`은 한 벌이므로 새 클래스는
  아홉 장 전부에 넣는다.
- 루트 `<svg>`에 `class="dg"`를 두고, `<style>`의 모든 규칙을 `.dg` 아래에 쓴다. 본문에
  인라인으로 들어가므로 `text { … }`처럼 벗은 선택자를 쓰면 페이지의 다른 SVG에 샌다.
- `<title>`과 `<desc>`를 반드시 쓰고 `aria-labelledby="t d"`로 묶는다. `<desc>`는 그림을
  못 보는 사람이 문단으로 읽을 수 있게 쓴다. id는 파일 안에서만 고유하면 된다 —
  인라인할 때 파일마다 다른 접두어가 붙는다.
- 글꼴은 `'Pretendard Variable', Pretendard, …, system-ui`. 인라인이라 페이지의 번들
  Pretendard를 그대로 받는다. 파일을 브라우저에서 직접 열 때만 시스템 고딕으로 떨어진다.

## 좁은 화면

960 좌표계의 15px 글자는 350px 화면에서 5.5px가 된다. 그래서 `figure.wide`는 620px
이하에서 스스로 가로로 밀린다(`overflow-x: auto` + `min-width: 600px`). 페이지 전체는
밀리지 않는다.

넓은 판과 좁은 판은 **같은 내용을 말해야 한다.** 칸을 합치거나 줄을 바꾸는 건 되지만
단계를 빼거나 이름을 바꾸면 화면 크기에 따라 다른 규칙을 읽게 된다. `<desc>`도 판마다
자기가 그린 것을 적는다 — 두 파일이 같은 `<desc>`를 쓰면 한쪽은 반드시 틀린 말을 한다.

세로로 다시 그린 판이 필요할 만큼 복잡한 그림은 마크다운에서 `<picture>`로 따로 둔다
(`ai-pipeline-risk-gates`가 그렇다). 빌드 때 두 장이 다 인라인되고 `data-only="wide"` ·
`"narrow"`가 붙어, `global.css`가 700px을 경계로 하나만 보인다. 좁은 판은 위 밀기 규칙에서
빠진다.

## 본문에 들어가는 방식

마크다운에는 전처럼 `<figure><img src="/images/…svg"></figure>`로 쓴다. 빌드 때
`src/lib/inline-svg.mjs`(Sätteri hast 플러그인)가 그 `img`를 파일 내용으로 바꿔 심는다.
`<img>`로 두면 SVG가 제 문서라서 페이지의 글꼴을 못 받고, 다크 값도 OS 설정만 따라가
사이트 토글과 어긋났다. 파일은 그대로 `public/`에 있으므로 주소로 직접 열 수도 있다.

마크다운의 `alt`는 이때 **버려진다.** 읽히는 것은 SVG 안의 `<title>`과 `<desc>`이므로
설명을 고칠 때는 그 둘을 고친다. `alt`는 파일을 직접 열었을 때를 위해 `<desc>`와 같은
말로 맞춰 둔다.

## 다시 그리기

아홉 장은 손으로 쓰지 않고 생성기로 만들었다. 좌표를 손으로 맞추면 한 칸을 옮길 때마다
선 여섯 개를 따라 고쳐야 한다. 생성기는 이 저장소에 두지 않았다 — 그림이 굳었고, 앞으로는
한 장씩 손보는 일이 더 많을 것이기 때문이다. 크게 다시 배치할 일이 생기면 그때 다시 짠다.

Inkscape로 열어 손볼 때는 두 가지를 알고 있어야 한다. Inkscape는 CSS 변수(`var(--…)`)를
못 읽어 칸이 전부 검게 보이지만 좌표는 정확하다. 그리고 Inkscape에서 저장하면 인라인
`style` 속성이 덧붙어 클래스 색과 다크 값이 깨진다. 그러니 Inkscape에서는 자리만 잡고,
좌표를 읽어 원본 SVG를 텍스트로 고친다.
