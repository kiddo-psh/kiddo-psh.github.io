# 프로젝트 글 개편 조사 · 2026-10-24

FDE는 현장의 불명확한 요구를 동작하는 시스템으로 옮기는 과정, AX는 업무 흐름을 바꾸고 그 효과를 검증하는 과정을 보여 주는 방향으로 편집한다. 이는 이 블로그의 편집 관점이며 특정 회사의 채용 기준을 대변하지 않는다.

## 편집 원칙

1. 도입에서 대상 사용자, 기존 업무, 바꾼 흐름, 본인 역할을 설명한다.
2. 대표 결정은 문제 → 선택 → 근거 → 대가 순서로 쓴다.
3. 팀 결과를 개인 성과로 바꾸지 않는다. 기술 목록은 팀 구성 기술임을 명시한다.
4. 커밋 수와 테스트 개수를 실력·품질의 대리 지표로 앞세우지 않는다.
5. 채택한 임계값의 미탐, 달라진 기준선, 목데이터를 숨기지 않는다.
6. 기록으로 확인되지 않는 동기·사용자 발언·팀 합의는 인터뷰 전까지 쓰지 않는다.
7. 서비스 실물과 증거 이미지는 보존한다. 새 설명 이미지는 기존 벡터 제작 방식과 디자인 씨드의 팔레트를 따른다.

## 인터뷰 질문

답변은 사실 / 당시 판단 / 회고를 구분해 받는다. 모르는 항목은 추정으로 채우지 않는다.

1. 주차바로: 관리사무소·차주를 실제로 인터뷰하거나 관찰했는가? 언제 누구에게서 어떤 불편을 확인했는가?
2. 주차바로: 상세 임계값 측정 보고서의 원본은 어디에 있는가? 기존 표의 미탐을 의도적으로 감수했다고 전제한 첫 질문은 철회한다. 프로젝트 종료일은 8월 10일/14일 중 어떤 기준인가?
3. 냠냠코치: Supervisor는 실제 실험인가, 설계 대안인가? 라우팅 개선의 계기가 된 사용자·팀 피드백은 무엇인가? 동일 프롬프트·정상 RAG 조건의 측정 원본이 있는가?
4. feelm: 계정·인증과 프론트 연동을 맡게 된 배경은? 계약 불일치 하나를 누가 발견하고, 어떤 대안과 일정 압박 속에서 합의했는가?
5. harness: 자동화할 만큼 반복된 실패 사례는? 실제 팀 도입의 사람·기간·피드백은? 목데이터와 실사용 기록은 어디서 구분되는가?
6. 공통: 가장 앞세울 프로젝트, FDE/AX 우선순위, 관심 기업·공고는? 본인이 최종 결정한 범위와 팀원이 구현한 범위를 확인해 달라.

## 1차 인터뷰 반영

- 주차바로: 거주민의 통로·라인 밖 주차 불편, 관리인의 이중주차·전기차 장기 충전 민원과 갈등 경험을 사용자 회고에 근거해 반영했다. 인원·일시·발언의 직접 인용은 만들지 않았다. 입주민 플랫폼 조사에서 불법/비매너 주차가 1위였다는 답변은 플랫폼 이름·원문·모집단이 없어 공개 글의 통계 근거로 사용하지 않았다.
- 임계값: 사용자는 ‘오탐 0건 선택’의 상황을 기억하지 못했다. 재조사한 `abbb849`와 `f87b3cc`는 구역 스침과 정차를 구분하기 위한 후보 탐색과 안전 마진을 설명한다. 후자는 0.5초 오탐 1건, 최소 실제 정차 0.733초, 다음 후보 1초를 기록한다. 상세 보고서는 로컬 docs와 HEAD에서 찾지 못했다. 기존 표는 제거하고 미탐 감수의 동기를 추정하지 않았다.
- 냠냠코치: 성능 테스트 중 예상보다 많은 토큰에서 불필요한 호출을 발견한 계기를 반영했다. Supervisor는 설계 비교라는 회고이며 시나리오 수에 대한 기억은 불확실하다. 평가 fixture 8개를 전체 서비스 시나리오 수로 바꾸지 않았다.
- feelm: 계정 담당으로 공격·보안을 의식한 배경을 반영했다. 대화 장면은 기억나지 않아 만들지 않았다. `d80dfb05`에서 OTT 일치도·이유 제거와 API/화면 계약 정리, `64532cd0`에서 실제 API 연동을 확인해 구체 사례로 추가했다. 커밋 작성자 정보는 판단 과정의 대화나 팀 합의를 증명하지 않는다.
- harness: 주차바로의 서로 다른 AI 개발 방식 → feelm 공통 규칙과 긍정적 팀 피드백 → CI·테스트 문제를 포함한 키트화 → Claude Code 팀 플랜의 토큰 부족과 AgentOps 필요성으로 서사를 보강했다. feelm의 규칙 사용과 완성된 키트 도입 리허설을 구분했다. 만족도를 정량 설문이나 생산성 개선율로 표현하지 않았다.

남은 확인: 입주민 플랫폼 조사 원문, 임계값 상세 보고서, 주차바로 종료일 기준, FDE/AX 우선순위·관심 공고. 이 정보 없이도 확인된 인터뷰와 코드 근거를 본문에 반영했다.

## 전면 재작성 형식

사용자가 승인한 형식을 실제 프로젝트 콘텐츠와 공통 화면에 반영했다. 제목 아래 핵심 주제·서비스 요약, 구성·기간·역할·기술, 직접 책임진 일·협업 범위·확인한 결과를 순서대로 배치한다. 목록에는 담당과 검증 수준을 노출한다. 기여율은 사용하지 않는다.

본문은 기존 문장 수정 대신 문제 발견 → 해결 범위 → 결정과 대가 → 검증 → 다음 판단의 서사로 새로 작성했다. 본문 안에서 반복하던 역할 설명과 과도한 편집 과정 설명은 줄이고, 중요한 측정 한계와 근거는 해당 사례 옆에 남겼다. 네 글의 중심 주제는 각각 현장 민원의 처리 흐름, 입력별 AI 실행 통제, 인증과 화면 계약, 공통 AI 개발 절차의 제품화다.
