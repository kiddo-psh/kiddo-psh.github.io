# FDE 포트폴리오 편집 기준 · 2026-10-24

대상: 마키나락스 FDE와 파수AI AI컨설턴트(FDE). “90점 이상”은 높은 완성도를 원하는 사용자 목표이며 회사의 실제 평가 점수나 합격을 보장하는 기준으로 사용하지 않는다.

## 공고에서 확인한 방향

- [파수AI 2026년 3차 신입 공고](https://recruit.fasoo.com/apply/299)의 [직무 이미지](https://career.fasoo.com/data/img/07-1.%20JD%20%28%EA%B8%B4%20%EB%B2%84%EC%A0%84%201%29_%EC%88%98%EC%A0%95.png): AI컨설턴트(FDE)의 기업용 AI 적용, 고객 도메인 데이터·RAG, 업무용 스킬·에이전트, 설명·소통과 보안 가이드 역할을 직접 확인했다. SW 컨설턴트와 같은 직무로 묶지 않는다.
- [파수AI 지원서 가이드](https://recruit.fasoo.com/fasoo-inside/26-3_guide): 경험의 규모보다 무엇을 의심하고 직접 확인했는지, 결과로 어떤 판단을 내렸는지가 중요하다고 설명한다. 이는 실제 기술 선택과 검증을 앞세우는 편집 근거다.
- [파수AI 개발자 인터뷰](https://recruit.fasoo.com/fasoo-inside/26-3_ai): 고객 환경에서 기술을 제품으로 연결하고 선택의 이유를 설명하는 경험을 참고했다. 문서 OCR·모델 학습 경력을 후보자에게 새로 부여하지 않는다.

아래 구성은 공고에 기반한 편집 판단이며 회사가 공개한 채점표가 아니다. 공고 문구를 후보자의 경력처럼 복사하지 않는다.

## 이전 페이지에서 고친 것

1. 최신 프로젝트 글과 어긋난 “오탐 0건으로 1초 선택”을 제거했다. 관측 조건과 안전 마진을 반영했다.
2. 관리 업무의 사람 손이 빠졌다는 효과 주장을 파일럿 시연 범위로 수정했다.
3. 프롬프트·검색 조건이 다른 지연 비교와 미확인 정상 응답률을 대표 성과에서 제외했다.
4. 구현·검증 근거가 이번 프로젝트 자료에서 충분히 뒷받침되지 않는 사진 분석의 독립 성과 섹션을 제거했다. 원본 연구나 데이터를 삭제한 것은 아니다.
5. 개발 키트를 초기 리허설만으로 설명하지 않고 이벤트 수집·작업 귀속·검증 근거까지 반영했다. 릴리스와 개발 브랜치를 구분한다.
6. feelm을 AI 밖의 부록으로 두지 않고 실패 처리·계정 상태·화면 계약을 구현한 네 번째 사례로 구성했다.
7. 큰 기술 목록 대신 프로젝트마다 직접 사용한 기술과 담당 범위를 붙였다.
8. 전체 형식을 첫 화면의 역할·연락처 → 핵심 경험 → 네 사례 → 팀 협업 → 배경·연락처로 교체했다.

## 배포 전 확인 기준

- 첫 화면에서 이름·지원 방향·직접 경험·연락처를 읽을 수 있다.
- 각 사례는 문제, 직접 맡은 범위, 선택 이유, 결과, 측정 조건, 상세 근거로 이어진다.
- 팀 최적화·목데이터·파일럿·개발 중 확장을 결과 가까이 표시한다.
- 확인되지 않은 고객 수·매출·절감률·운영 기간·모델 학습 경험을 넣지 않는다.
- 제목과 설명은 처음 읽는 사람도 문제 상황을 이해할 수 있게 쓴다.
- 초록·회색 시드를 유지하고 작은 화면에서 두 열을 한 열로 바꾼다.
- 연락·이미지 원본·상세 글·저장소 링크는 실제 목적지로 연결한다.
- 인쇄/PDF 저장은 브라우저 인쇄 기능이며 완성된 PDF 파일 다운로드로 표시하지 않는다.

## 실제로 더 강하게 만들 근거

문장만으로 대체하지 않는 항목이다. 아래 자료를 확보하면 사례의 설득력을 추가로 높일 수 있다.

1. **사용자 요구의 추적:** 익명화한 인터뷰 원문, 요구가 바뀐 사례, 완료 기준과 사용자 확인 기록.
2. **도입 이후의 측정:** 실제 현장/사용자에서 실패율·처리시간·개입 횟수의 정의와 전후 기록. 파일럿이면 파일럿임을 명시.
3. **AI 품질 평가:** 정상 검색·동일 모델/프롬프트에서의 지연·비용 재측정, 답변 품질 및 누락 분석 평가.
4. **실행 가능한 증거:** 공개 가능한 재현 명령·샘플 입력·평가 결과·짧은 데모, 프로젝트별 저장소 링크와 개인 기여 경로.
5. **기업 환경의 조건:** 접근권한·보관/삭제·관측 데이터의 경계와 장애 복구 실험. 현재 인증과 원문 비수집을 기업 보안 준수 전체로 확장하지 않음.

이번 변경은 로컬 검토용이다. 공식 지원·메시지 전송·공개 배포는 수행하지 않는다.

## AgentOps 요약 보강

홈의 대표 프로젝트 3개 제한과 `featured: false` 때문에 AI-Dev-Harness가 노출되지 않던 문제를 수정했다. 대표 4개를 포트폴리오 순서로 표시하고, 데스크톱에서는 2×2로 배치한다.

홈 카드에는 공통 사용량 정규화, 세션·작업·PR 연결, 중복 제거·실패 재전송, 테스트와 코드 상태 연결, OTel·Prometheus·Loki·Grafana, 꾸기 적용 이력을 요약한다. 포트폴리오의 세 번째 사례도 같은 관점으로 갱신한다. 64분 리허설은 초기 설치·검사 근거로 상세 글에만 남기고 대표 성과로 쓰지 않는다. 0.4.0 릴리스와 확장 개발 브랜치, 적용 이력과 생산성 효과는 계속 구분한다.
